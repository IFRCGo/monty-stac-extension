    IDU

    The IDU(Internal Displacements Updates) tracks the number of the people who are internally displaced in a region or a country due to disaster or conflict.

    Note: As of now, we only deal with disaster type events.

    Data Sources

    API: https://helix-tools-api.idmcdb.org/external-api/

    Current Usage: https://www.internal-displacement.org/internal-displacement-updates/

    Collection: idmc-idu-events

    Collections: idmc-idu-events and idmc-idu-impacts

    Two STAC collections hold the IDU data: one for the events, and one for the displacement figures of each event.

    Name: Internal displacement updates

    Code: IDU

    Source organization: Internal Displacement Monitoring Center (IDMC)

    Source organization type: International NGO

    Source organization email: info@idmc.ch

    Source code: IDMC

    Source URL: https://helix-tools-api.idmcdb.org/external-api/

    Source Data license: None stated by the source (checked 2026-07)

    Source for: event, impact

    previous implementation (R): none

    Which records are ingested

    The reference files are in the IDMC folder: idu-export.json (a full export) and idmc-idu-samples-ESP.json (the records of Spain).

    • Only the records with displacement_type = Disaster are ingested. Conflict and Other records are ignored.
    • A record must have the fields latitude, longitude and event_id. A record without one of them is ignored, with a warning.
    • The Recommended figure records and the Triangulation records are all ingested. The role field gives the estimate_type of the impact item.
    • The transformer groups the records by event_id. Each group gives one event item, and one impact item for each record of the group.
    • If one record of a group is not valid, or the hazard of the event is not in the hazard type mapping, the transformer skips all the group and counts its records as failed. It continues with the next group.

    On idu-export.json (4623 records, 2586 of them Disaster), the transformer gives 1673 event items and 2585 impact items. One record fails: its hazard is Mixed disasters.

    Event Item

    The event item is built from the first record of the event. Only monty:country_codes uses all the records.

    STAC field IDU Field Remarks
    id idmc-idu-event-{event_id} Prepend text for uniqueness
    collection idmc-idu-events Collection name for STAC
    title event_name Name of the event
    description standard_popup_text Converted from HTML to Markdown
    datetime event_start_date Start date of the event, UTC
    geometry longitude, latitude A Point. The location of the first record of the event
    bbox longitude, latitude The same point
    monty:country_codes iso3 of all the records of the event No duplicates. The country of the first record is first, because monty:corr_id uses the first code
    monty:episode_number Generated This is a fixed value (1)
    monty:hazard_codes Based on category, subcategory, type, subtype List of hazard codes, from the hazard type mapping
    monty:corr_id Generated Generated following the event pairing procedure
    monty:src_event_id event_id The source identifier of the event, as a string
    keywords Generated The keywords of the hazard profile, then the country codes
    properties.location locations_name One string. The name is location, without s
    properties.start_datetime event_start_date
    properties.end_datetime event_end_date
    properties.sources sources
    properties.roles [event, source] Include both event and source roles (order does not matter)
    asset.report source_url Only when the record has a source_url. The media type is always application/pdf
    via link in [links] URL of the source data The URL that the data came from, not the source_url of the record
    related links in [links] each impact item of the event roles: ["impact"]
    processing:version Generated Semantic version of the transformer that generated the item, via the processing: extension
    processing:software Generated Dependency/provenance chain ({"pystac-monty": "<version>"}), via the processing: extension

    The transformer does not write monty:event_codes. The IDU field event_codes is not mapped.

    Hazard Type Mapping

    The IDMC hazard classification has four levels. The UNDRR-ISC 2025 code is the reference classification for the Monty extension. IDU and GIDD use the same mapping:

    The comparison is not case-sensitive. The transformer writes the three codes in the order UNDRR-ISC 2025, GLIDE, EM-DAT, for example ["MH0600", "FL", "nat-hyd-flo-flo"].

    A hazard that is not in this table gives no item: the transformer skips all the records of that event and counts them as failed. This includes Mixed disasters. The transformer has a row for it (mix-mix-mix-mix), but that value has no UNDRR-ISC 2025 code, so the event fails.

    Impact Item

    Each Disaster record gives one impact item. The transformer starts from a copy of the event item, and then sets the fields of the record. So an impact item also has the title, monty:corr_id, monty:hazard_codes, monty:episode_number and monty:src_event_id of its event.

    STAC field IDU Field Remarks
    id idmc-idu-impact-{event_id}-{id}-{impact_type} See Impact item id
    collection idmc-idu-impacts Collection name for STAC
    title event_name Name of the event. All the impact items of an event have the same title
    description standard_popup_text Of the record. Converted from HTML to Markdown
    datetime displacement_start_date UTC
    properties.start_datetime displacement_start_date
    properties.end_datetime displacement_end_date
    geometry longitude, latitude A Point. The location of the record
    bbox longitude, latitude The same point
    monty:country_codes iso3 One code: the country of the record
    keywords Generated The keywords of the hazard profile, then the country code of the record
    properties.location locations_name Of the record
    properties.sources sources Of the record
    properties.roles [impact, source] Include both impact and source roles (order does not matter)
    asset.report source_url Of the record. No asset when the record has no source_url
    via link in [links] URL of the source data Same as the event item
    related link in [links] the event item roles: ["event"]
    monty:impact_detail impact_detail As shown in Impact Detail below
    monty:src_event_id event_id The identifier of the event, not of the record
    processing:version Generated Semantic version of the transformer that generated the item, via the processing: extension
    processing:software Generated Dependency/provenance chain ({"pystac-monty": "<version>"}), via the processing: extension

    Impact item id

    The id is idmc-idu-impact-{event_id}-{id}-{impact_type}:

    • {event_id} is the identifier of the event, and {id} is the identifier of the record.
    • {impact_type} comes from standard_popup_text. The transformer takes the first text between parentheses. If that text is a label of the Impact Detail table, it is the impact_type. If not, or if there are no parentheses, the impact_type is displaced.

    Example: the text 200 displacements (evacuated), 11 November - 11 November gives idmc-idu-impact-28177-169470-evacuated.

    Important

    The id has a hyphen between {event_id} and {id} since IFRCGo/pystac-monty#268. Before that change the transformer wrote the two numbers with no separator (idmc-idu-impact-28177169470-evacuated). This doc and its examples gave a third form, idmc-idu-impact-{id}-displaced, which no transformer release wrote.

    Impact Detail

    The impact_type gives the category and the type of monty:impact_detail. The comparison is case-sensitive:

    Label category type
    evacuated people evacuated
    displaced people displaced_internal
    relocated people relocated
    sheltered people shelter_emergency
    homeless people homeless
    affected people affected_total
    IDPs people displaced_internal
    Internal Displacements people displaced_internal
    Deaths people death
    People displaced across borders people displaced_external

    An impact_type that is not in the table gives people / displaced_internal.

    Key Value
    category from the table above
    type from the table above
    value figure field of the record
    unit count
    estimate_type from the role field (see below)

    The role field of the record gives the estimate_type:

    role estimate_type Meaning
    Recommended figure primary The figure that IDMC recommends for the event
    Triangulation secondary A figure from a second source, which IDMC uses to check the recommended figure
    other value, or none primary

    Warning

    A Triangulation figure is not an additional number of people. It can describe the same people as the recommended figure of the event. To get the total of an event, add only the primary values.

    Examples

    The examples are the output of the transformer for idmc-idu-samples-ESP.json. Only the links are adapted to the layout of examples/.

    • idmc-idu-event-28064 and idmc-idu-impact-28064-168623-displaced: a flood in Andalusia, 4 210 people displaced
    • idmc-idu-event-28177 and idmc-idu-impact-28177-169470-evacuated: a wildfire in the Canary Islands, 200 people evacuated

    In a deployment, the related hrefs have the form {eoapi_url}/collections/{collection}/items/{item_id}.
