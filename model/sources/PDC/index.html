    Pacific Disaster Center (PDC)

    The Pacific Disaster Center (PDC) tracks a wide range of natural and human made hazards viz. Tropical Cyclone, Earthquake, Flood, Landslides, Wildfire, Drought, Volcanic Eruptions etc to support disaster preparedness, response, and risk reduction efforts.

    This document describes the PDC transformer at IFRCGo/pystac-monty@b831436 (pystac_monty/sources/pdc.py). Each statement about the items was checked by a run of that transformer on the upstream fixtures in tests/data/pdc/ (hazard 313159, a landslide in Peru), and on variants of them: no exposure data, two snapshots, two countries and an unknown hazard type.

    Collection: pdc-events

    A STAC collection hold all the PDC events.

    • Name: Pacific Disaster Center
    • Code: PDC
    • Source organization: Pacific Disaster Center
    • Source code:
    • Source type: International Organization
    • Source organization email: info@pdc.org
    • Source URL: https://www.pdc.org/
    • Source Data License: Restricted — disaster/emergency management use only, no redistribution without authorization (PDC Terms & Conditions)
    • Source for: event, hazard, impact

    The three PDC collections (pdc-events, pdc-hazards, pdc-impacts) are marked private (#195), because of this license.

    Examples: the transformer output for the upstream fixture, with the self, collection and related links changed to point into this repository, and only two of the 19 impact items:

    • Event: pdc-event-f2762e72-5169-487e-a3fa-30e21fc55893-313159.json
    • Hazard: pdc-hazard-f2762e72-5169-487e-a3fa-30e21fc55893-313159.json
    • Impact, total population: pdc-impact-…-population-total-PER-0.json
    • Impact, capital: pdc-impact-…-capital-total-PER-0.json

    Data flow

    The ETL (montandon-etl, apps/etl/etl_tasks/pdc.py and apps/etl/extraction/sources/pdc/extract.py) uses these PDC Sentry endpoints:

    1. Hazard list: POST https://sentry.pdc.org/hp_srv/services/hazards/t/json/search_hazard, with a createDate window. The window starts at PDC_START_DATE (default: the first day of the current month) and ends now.
    2. Exposure list of each hazard: https://sentry.pdc.org/hp_srv/services/hazard/{uuid}/exposure. It gives the timestamps of the exposure snapshots.
    3. Exposure detail of each snapshot: https://sentry.pdc.org/hp_srv/services/hazard/{uuid}/exposure/{timestamp}.
    4. Hazard area (GeoJSON): https://sentry.pdc.org/hp_srv/services/mags/1/json/get_mags?hazard_id={hazard_ID}.

    The ETL keeps a hash of each exposure detail, without its timestamp. A snapshot with the same content as the one before it is not sent again to the transformer.

    Transformer input

    PDCDataSource takes a PDCDataSourceType:

    PDCDataSourceType(
    source_url: str,
    uuid: str,                                   # the PDC hazard uuid
    hazard_data: File | Memory,                  # the hazard list (search_hazard response)
    exposure_detail_data: list[File | Memory],   # zero, one or more snapshots of this hazard
    geojson_path: str,                           # where the hazard area GeoJSON is stored
)

    exposure_detail_data can be empty. A single File or Memory is also accepted.

    Items made for one PDC hazard

    Item Number Condition
    Event 1 Always, when type_ID is in the Hazard Type Mapping
    Hazard 1 Same as the event
    Impact One per snapshot × impact field × totalByAdmin row Only for a valid snapshot, and only when the field has a value

    For the upstream fixture (one snapshot, one totalByAdmin row), the transformer makes 21 items: the event, the hazard and 19 impact items. With a second snapshot that has three totalByAdmin rows, it makes 78 items: the event, the hazard, 19 impact items for the first snapshot and 57 for the second.

    geometry latitude, longitude Point

    Note

    The earliest snapshot comes first, so a new snapshot can only add countries at the end of monty:country_codes. The first code, and so monty:corr_id, stays the same (IFRCGo/pystac-monty#273, #276). The rules for multi-country items are in monty:country_codes.

    Hazard Type Mapping

    PDC (Pacific Disaster Center) tracks a wide range of natural and geopolitical hazards. The 2025 UNDRR-ISC code is the reference classification for the Monty extension. The transformer maps the type_ID value of the hazard:

    Natural Hazards:

    Avalanche AVALANCHE AV nat-hyd-mmw-ava MH0801 MH-TERR Avalanche
    Biomedical BIOMEDICAL EP nat-bio-epi-dis BI0101 BIO-INFECT Infectious Diseases
    Drought DROUGHT DR nat-cli-dro-dro MH0401 MH-PRECIP Drought
    Earthquake EARTHQUAKE EQ nat-geo-ear-gro GH0101 GEO-SEIS Earthquake
    Extreme Temperature EXTREMETEMPERATURE HT nat-met-ext-hea MH0501 MH-TEMP Heatwave (also for cold, see the note)

    Note

    All three classification codes (GLIDE, EM-DAT, UNDRR-ISC 2025) should be included in the monty:hazard_codes array for maximum interoperability. A type with no EM-DAT code (CYBER, OCCURRENCE) gets only two codes. More specific hazard codes can be added following the characteristics of the event.

    Extreme Temperature: the transformer always uses MH0501 (Heatwave) and HT, also for a cold event. The correct codes for a cold event are MH0502 and CW. PDC gives no field that tells heat from cold, so this is not fixed yet.

    Unknown type_ID: the transformer logs a warning, makes no item for the hazard, and counts the hazard as a failed row.

    Scope decision — HIGHWIND (pystac-monty#196): PDC issues HighWind from NWS High Wind Warnings/Advisories — sustained wind of 40 mph (35 kt) or more for 1 hour or more, or gusts of 58 mph (50 kt) or more, when no tropical cyclone or thunderstorm is present. This is a general wind event, not a Beaufort-scale term. So it maps to MH0301 (Wind), not MH0303 (Gale). This choice follows the existing GLIDE↔EM-DAT↔UNDRR crosswalk in taxonomy.md (VW → nat-met-sto-sto → MH0301).

    Hazard Item

    The hazard item is a copy of the event item, with these differences:

    STAC field Value Description
    id pdc-hazard-{uuid}-{hazard_ID} The event id with the pdc-hazard- prefix
    collection pdc-hazards
    roles Fixed ["source", "hazard"]
    monty:hazard_codes Derived The UNDRR-ISC 2025 code only, e.g. ["GH0300"]
    monty:hazard_detail severity_ID See below
    related links Generated To the event item and to each impact item

    All the other fields (geometry, datetime, monty:country_codes, monty:corr_id, keywords, assets) are the same as the event.

    {
  "severity_value": 0.1,
  "severity_unit": "PDC Severity Score",
  "severity_label": "<severity_ID, e.g. WARNING>",
  "estimate_type": "primary"
}

    Warning

    severity_value is always 0.1. It is a placeholder, because the schema requires a value and PDC gives no number. Do not use it. The PDC severity is in severity_label.

    Impact item

    The transformer makes one impact item for each snapshot, each impact field and each row of totalByAdmin, when the field has a value in that row. A field without a value gives no item. An invalid snapshot is skipped with a warning; the event and the hazard are still made. When two snapshots have the same timestamp, the transformer keeps the last one.

    The impact item is a copy of the event item, with these differences:

    STAC field Value Description
    id Generated pdc-impact-{uuid}-{hazard_ID}-{timestamp_ms}-{episode}-{group}-{field}-{admin}, see below
    collection pdc-impacts
    datetime timestamp of the snapshot Converted to UTC. start_datetime and end_datetime stay the same as the event
    roles Fixed ["source", "impact"]
    monty:country_codes totalByAdmin[].country The country of the row. One code
    monty:impact_detail The field See Impact Detail
    related links Generated To the event item and to the hazard item

    The geometry (the hazard point), monty:hazard_codes (all three codes), monty:corr_id, keywords and assets are the same as the event. So the keywords of an impact item can name other countries than its monty:country_codes.

    The parts of the impact id:

    • {timestamp_ms}: the snapshot timestamp in milliseconds. PDC sends milliseconds or seconds with decimals (1738897884.7774327 in the fixture). A value below 10¹¹ is read as seconds.
    • {episode}: always 1.
    • {group}-{field}: the impact field, e.g. population-total0_4, capital-total.
    • {admin}: the country of the row, then admin1 and admin2 when they have a value, in lowercase ASCII (San Martín → san-martin), then -0. When a row has the same country/admin1/admin2 as a row before it, -0 becomes the row index (-1, -2, …).

    Example: pdc-impact-f2762e72-5169-487e-a3fa-30e21fc55893-313159-1738897884777-1-population-total-PER-0.

    Note

    These values are PDC exposure estimates: the people and the assets in the hazard area. They are not observed impacts. The capital.total value is in USD, but the item has no unit. How Monty represents exposure is open in #169 and Discussion #110.

    Limitations and exclusions

    • Hazards without exposure data. Such a hazard gives an event item and a hazard item, but no impact item (IFRCGo/pystac-monty#274).
    • Historical hazards. For most old hazards (e.g. 2010 or 2015), the exposure list endpoint returns 404 Not Found (IFRCGo/montandon-etl#425). There is no other endpoint for this data. These hazards can have event and hazard items only. PDC offered targeted exports of its historical database on request.
    • Unchanged snapshots. The ETL does not send a snapshot that has the same content as the one before it, so such a snapshot gives no impact item.
    • Unknown hazard types. A type_ID that is not in the Hazard Type Mapping gives no item.
    • Fields not mapped. A totalByAdmin row has more fields than the 19 in Impact Detail. These are not mapped: the other population groups (total0_14, total15_64, total65_69 to total95_99, total100AndOver, vulnerable, vulnerable0_14, vulnerable15_64, vulnerable65_Plus), and the needs (foodNeeds, waterNeeds, wasteNeeds, shelterNeeds) with their units. total65_Plus (mapped) and total65_69 to total100AndOver (not mapped) overlap.
    • No polygon geometry. All the items have the hazard point as geometry. The hazard area is only in the Maps asset.
